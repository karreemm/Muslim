## Summary

- Added `docs/ui-ux-guidelines.md`: tokens, typography, layout, components,
  theming, RTL, states, motion, media, accessibility, copy, and a review
  checklist.
- Added `docs/operations.md`: environments, env-var matrix, Supabase contract and

- Drafted a public/private visibility model while the security guide existed; the
  owner later removed it from the repository by request.
- Added an MIT `LICENSE`, resolving the mismatch between the README's
  "open source" claim and the absence of a license file.
- Added repository metadata to `package.json` (license, repository, homepage,
  bugs) so the package points at the real project.
- Hardened `.gitignore` so only `.env.example` can ever be committed.
- Revised the full document set: normalized front matter, removed duplicated
  sections that now live in the new guides, and corrected stale facts
  (palette single sourcing, legacy `NEXT_PUBLIC_HADITH_API_KEY`, browser matrix,
  React version, clone URL, broken anchors).
- Added contributor files: `CONTRIBUTING.md`, issue forms, a PR template, and
  Dependabot.
- Condensed every living guide and the root README to their essentials; removed
  duplicated detail and long per-endpoint documentation.
- Deleted `docs/security.md`, the security section, and `CHANGELOG.md` at the
  owner's request. Remaining guidance lives in `CONTRIBUTING.md`, the environment
  matrix, and the tests; release history stays in git and `docs/changes/`.
- Removed the visual regression suite, its config, snapshots, workflow, scripts,
  and CI jobs. It required platform-specific baselines and was not paying for its
  maintenance cost.

## Context / Problem

The repository claimed two living guides that did not exist:
`docs/ui-ux-guidelines.md` and `docs/operations.md` were referenced from
`docs/README.md` as "planned". Contributors had to reverse-engineer token rules,
state requirements, and deployment steps from code.

In parallel, the project is public, so the boundary between "safe to publish" and
"must never be published" needed to be written down rather than assumed.

## Scope

### In scope

- Writing the two missing living guides.
- Auditing what is already public: tracked files and full git history.
- Documenting the exposure model, secret rotation, and incident runbooks.
- Fixing documentation that no longer matched the code.

### Out of scope

- Changing runtime behaviour, headers, or API contracts.
- Enabling GitHub secret scanning / push protection (repository settings).

## Architecture & Patterns

- Living guides describe the system **today** and are updated in place; change
  records are append-only history.
- The guides link to each other instead of duplicating detail:
  UI → overview/testing, ops → security/api/testing.
- The exposure model states a rule rather than a list of moods: if a control only
  works because the code is hidden, it is not a control.
